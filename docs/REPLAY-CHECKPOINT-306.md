# 306 可信重放检查点

本轮补首版方案中大账本启动恢复的差异。继承 302–305 的事件权威、异步派生、共享线程和旧验证；不重发原模型任务，不覆盖 297 冻结候选。当前检查结果以 `reports/replay-checkpoint-306/result.json` 为准；该文件生成前仍在实施和验证中。

本轮最终相关 Rust 检查 104 项通过，另完成新检查点文件与 297 冻结读者的隔离往返兼容检查；严格核心 all-targets Clippy、格式及本轮差异检查通过。首次错误断言、日报异步等待缺失、旧提示断言和受限 IPC 失败均保留，详见[本轮结果](../reports/replay-checkpoint-306/summary.md)。这是限定范围工程验收，正式发布验收仍未完成。

## 权威与保护边界

普通 Store 和严格 DurableWorkflow 都保存可丢弃的 `replay-checkpoint.dpapi`。它不是批准输入、不是新的事件来源，也不是签名产物。Windows 当前用户 DPAPI 保护缓存，独立于模型凭证的命名空间；不使用 API Key、不创建应用签名密钥、不修改系统信任。DPAPI 不能抵御以同一 Windows 用户身份运行的恶意代码，不能宣传为独立安全域。

保护绑定原 canonical 目录、当前可执行文件 SHA256、缓存 schema、账本种类和工作流 bindings 摘要。使用程序摘要而不只使用版本号，因为 302–306 都仍为开发中的 0.1.20。用户/目录/程序或配置变化时回退完整重放。

每条事件的文件名、长度与原始字节 SHA256 在读取校验通过或成功提交时保存在内存。后台只密封这一份证明，不重新读取事件后用新摘要给旧内存状态作保证。恢复会枚举当前真实事件集合，逐条验证缓存前缀的原始字节，命中后才恢复状态和历史；尾部仍走完整序号、哈希链、上下文、执行证据和状态机检查。删除、插入或修改事件不能由缓存掩盖。普通 state.json 和 SQLite 始终不参与恢复授权。

## 当前权限及重开行为

- 每条缓存工作流事件仍检查 `reader_generation::require_workflow_context`，API 费用核对确认仍检查当前 `currency_api_resolution_guard`。这些动态检查不能被缓存跳过。
- 其余重复重放校验只在相同程序、相同配置、相同已验证事件字节的保护范围内复用。以后新增读取外部状态的重放规则，必须同时加入检查点命中路径的动态检查。
- 状态机恢复沿用原构造器的主体和执行模式，不能由缓存替换权限绑定；恢复方法仅供可信 durable host 调用，无 RPC 入口。
- `restore_current` 仍执行，Dispatching/Running/Cancelling 仍产生原来的 Unknown 恢复事件；不会重新派发，不能通过缓存释放未决任务的资源。
- 后续实际 Accept 等命令仍核查当前文件和验收证据。历史缓存命中不等于当前产物重新验收通过。
- `inspect_existing` 继续完整重放，不写入、修复或信任检查点。

## 写入、范围与局限

每增加至少 256 条事件才捕获检查点；首次完整读取达到该数量也可生成。复用 305 的最多 2 个线程、128 个处理中账本链和每账本一个 pending。较新的索引快照不能吞掉尚未写入的检查点。检查点、日报和 SQLite 独立发布；检查点失败不能改变权威命令成功或导致自动重发。关闭账本仍等其后台文件操作结束后释放 writer.lock。

本轮限制检查点前缀为 65536 条、原始事件累计 8 MiB，序列化明文最大 32 MiB，密文输入最大 32 MiB + 64 KiB。超过范围就不再生成更大的检查点，事件和完整重放仍有效。这只限制检查点组件，不等于整个产品或全部投影已有硬内存预算。全部历史仍在内存，主线程仍有 O(n) 克隆/日报预渲染，启动仍要读取并散列缓存前缀的所有文件。不能据此声称恒定时间恢复或所有大账本优化完成。

缓存文件拒绝符号链接、reparse point 和读取硬链接，限制读取长度；原子发布只清理自己 create_new 成功创建的临时文件。旧读者忽略这一派生文件，不改变事件 schema 或 reader generation。真正发行前仍须新核心隔离历史回读、新包、许可证和签名/安装全量核查。

## 验证口径

新增差异覆盖有效前缀与尾部、批准幂等/过期摘要拒绝、损坏缓存回退、坏事件停止、程序/目录绑定、事件提交后外部改动、pending 合并、派生失败隔离、字节/链接边界、Unknown 恢复、只读检查和严格编程 Accept。费用 guard 的白盒用例仅验证命中路径仍执行动态门禁，不把伪造的测试 envelope 算作真实用户费用操作。
