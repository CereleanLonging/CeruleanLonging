# OMP 文件工具执行与提交 V1

2026-10-10。文件服务现在已接入批准任务的OMP工作流桥接入口 `dispatch_with_files`。这一步连接了此前分开的文件工具和任务提交；生产RuntimeHost后台任务/桌面启动入口仍需接入。

## 执行路径

入口先核对批准、原尝试、Assigned状态、请求次数及预算，再在工作流固定派生的位置建立全新的文件证据目录，依据批准权限注册读写工具。沿用单个已连接、受信调用方独占的OMP通道。注册失败不会发模型prompt；已有工具目录不可复用，后续宿主需要把未发送启动失败纳入明确收口流程。

工作流DispatchIntent和prompt journal都落盘后才发送。工具Dispatch/Result各自先记录再执行/回传。模型完成或取消消息需与请求匹配，并等待工具处理器结束及新的空闲状态；完成传输后释放文件服务，再独立读取工具journal，要求所有调用已有本地结果。

Completed终态先持久化，然后捕获原产物、封存，再提交。封存增加可选toolHead，绑定完整工具日志末条哈希；零调用工具目录使用genesis。新文件工具执行必须有工具证据目录。旧无工具封存省略字段，保留其序列化/哈希格式。提交和恢复重新读取并比较工具头及原产物，不能用重启后的文件重新捕获缺失封存。

有本地工具结果不等于OMP收到回传；Submitted不等于验收通过。独立验证器检查后才允许主指挥Accept。取消和失败可能保留已经发生的文件修改：取消不自动回滚，失败/丢失终态进入Unknown，原写入记录可用于已有复核入口。

## 实际进程终止验证

测试通过模拟RPC对端发起真实受控文件写入，由父测试仅终止自己创建的执行子进程，覆盖六个边界：

| 终止位置 | 重开表现 |
| --- | --- |
| 原终态已记录，尚未封存 | Unknown；缺失封存，拒绝恢复提交 |
| completion.pending已同步 | Unknown；未完成发布，拒绝恢复 |
| completion.json已发布但pending尚在 | Unknown；证据仍未收口，拒绝恢复 |
| 封存提交完成 | 只使用原封存及完整工具证据恢复Submitted |
| 产物已封存，尚未工作流提交 | 同上；不发新prompt、不重放工具 |
| 工作流提交完成 | 重开即Submitted；拒绝重复应用 |

每个位置均保留实际写入内容和一个已完成工具调用；没有凭空增加工具调用或验收。子进程/临时目录由测试创建和回收。这是进程终止验证，不证明断电或介质故障恢复能力。

## 联合检查

新增四组测试：一是实际文件工具→Submitted→独立验证→Accepted，以及写入后的取消/提供方错误/丢失终态；二是封存后的工具日志完整/缺失/截断/损坏及拒绝重发；三是不支持的金额预算在注册和文件服务创建前拒绝；四是上述六个位置的实际进程终止矩阵。另有一个忽略的子进程入口供父测试调用。
