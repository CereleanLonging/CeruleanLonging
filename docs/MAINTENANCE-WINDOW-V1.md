## 使用顺序

1. 在桌面“维护与升级”页打开独立窗口，保存展开项里的维护副本目录与会话摘要。打开仅准备工具副本，不会停止核心或升级程序。
2. 在维护窗口审阅升级状态，核对后勾选本次操作确认，再锁定并停止核心；也可读取已经存在的锁定。
3. 填入原安装包与新安装包目录，分别读取清单，核对版本及摘要。内部未签名通道须明确选择；正式通道需要发布者证书指纹。准备动作还会检查实际文件与签名，读取清单本身不代表包已通过审查。
4. 选择与原安装同卷、互不重叠的新事务目录，确认后准备备份和程序，保存返回的事务计划摘要。
5. 关闭所有原工作台窗口，保留独立维护窗口；明确执行更新。审阅结果后确认完成升级，或在允许的状态恢复原程序。工具不自动重开项目。
6. 遇到中断，先用原事务目录、原计划摘要读取事务；按已保存凭据决定对账、放弃未完成提交或回滚。失败不自动重试。旧 098 未释放意图的限制仍适用。

每次变更都需要重新勾选确认；操作运行时输入和按钮锁定，关闭窗口会被阻止直到该子进程退出。每项操作的请求、输出、错误与退出记录保存在维护副本的 `operations` 目录。若维护宿主本身异常退出，子进程是否还运行必须核对，不能仅凭缺少完成记录再次发送。

## 分发与进程边界

Rust 编译时嵌入维护界面、更新事务和候选包审查三个脚本。打开时在安装目录及数据目录之外创建唯一会话副本，复制当前核心，保存 schema1、版本、当前用户 SID、目录和四份文件的摘要。脚本以带 BOM 的 UTF-8 写入，适配 Windows PowerShell 5 中文解析。文件禁止覆盖并落盘；原文件/目录检查拒绝重解析点及硬链接。

独立窗口校验会话摘要、SID、目录与工具清单，持有文件读取句柄；更新动作再由原事务组件核对安装、包、数据与锁。维护副本不占用待替换安装目录。主界面只返回新进程 PID 和恢复信息；进程已创建不等于窗口加载成功，更不等于升级完成。

启动保持 Windows PowerShell `RemoteSigned`，不修改系统执行策略。Rust 将规范化路径转回普通 DOS/UNC 表示，避免 PowerShell 5 把本机扩展路径误判为远程脚本；同时明确设置该子进程使用 Windows PowerShell 自带模块目录，避免继承 PowerShell 7 模块路径后找不到 `Get-FileHash`。这两项修复的失败日志仍保留。

重新打开原副本时，使用其原 `maintenance-window.ps1`、`session.json` 和原会话摘要。工具不自动选择最近事务，不从未核对的目录恢复动作。当前尚无图形化历史维护会话选择器或主界面加载就绪回执。
