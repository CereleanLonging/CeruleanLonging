# 待对账验收的显式放弃 v1

2026-10-08。实现 `verification_reconciliation.rs`、宿主 AbandonVerification 窄命令和桌面确认弹窗。当前支持保留证据后放弃未知结果；不把未知结果人工升级为通过。

## 操作与不变量

1. 仅 Unknown 且验收线程已结束、项目账本可用的记录提供审阅入口。Running/Cancelling、已有正式 Verify 的结果不可放弃。无法安全读取证据时不提供可提交的摘要。
2. 界面固定审阅时的记录和摘要，要求填写原因，并明确说明任务不会因此通过、不会自动重跑。用户命令只有 projectId/operationId/digest/reason，无任意角色、命令或 passed。
3. 摘要覆盖项目、任务、尝试、验收操作、启动时间、当前账本末条哈希，以及 intent.json/result.json/snapshot.json 的原始字节摘要或缺失状态。提交时重新计算；审阅后新增结果、修改证据或改变账本均拒绝旧确认。
4. 原操作目录内新增 abandonment.json，先同步临时文件再发布；包含固定 user 身份、原因、时间、操作绑定与证据摘要。原日志、输入副本、损坏结果和意图均保留，不覆写失败记录。随后更新可重建的 Abandoned 状态视图。
5. 重启以审计文件和当前证据校验恢复。相同请求重复返回既有决定，不覆盖原因或重新执行。伪造状态标签而没有有效审计不会被信任；放弃后的关键证据变化会回到 Unknown。
6. 新 runner 只跳过通过校验的已放弃操作，旧 ID 永久占用。后续新检查仍需可信宿主显式启动，并重新核验批准、尝试、产物和工具来源。放弃本身不启动线程、不写 Verify/Accept、不改变 task.verified。

## 剩余边界

此处“对账”只提供放弃分支及已有 Verify 的恢复。没有提供把仅落在磁盘、尚未入账的成功报告直接认定通过；该分支仍需可信来源和封存副本复核后设计。证据篡改导致旧审计失效时，继续阻止运行，不允许覆盖原决定来掩盖变化。

审阅摘要覆盖上述三个控制文件与账本绑定，不宣称核对了全部原始 stdout/stderr、临时文件或外部副作用。audit 与账本一样受本机文件完整性边界限制，不能防止同账号恶意程序重写所有文件。没有跨 Windows 用户或系统服务逃逸隔离声明。

放弃验收不等于取消业务任务。submitted 任务仍需之后的重验/任务取消/收口流程，因此不会自动解除所有核心退出限制。工作流重启后的 Job 生命周期清理沿用已验证的运行器；线程仍活跃或账本恢复失败时必须先解决该情况。
