# 291：旧项目 IANA 规则的运行时护栏

2026-10-23。延续 235 的项目时区实现和 288 的内部候选，不修改旧项目、旧冻结证据或已发布包。

`chrono-tz` 当前精确锁定为 0.10.4，所带 IANA 数据库版本为 2025b。此前只有单元断言能在测试时发现规则变化；若未来构建流程漏跑该断言，新二进制仍可能按新规则重建 schema 2/3 项目的历史日报。本轮在 `SchedulerConfig::validate_timezone` 的账本打开/创建入口和命名时区日报的公开入口加入运行时核对。规则不是 2025b 时，在读取并投影事件或创建新账本目录之前拒绝；schema 1 的旧上海固定 UTC+8 路径继续独立运行。

差异仅涉及 `crates/domain/src/timezone.rs`、`crates/core/src/scheduler.rs`、`crates/core/src/handoff.rs`。针对性检查：`cargo fmt --all -- --check`、`git diff --check` 通过；domain 版本护栏 1/1、handoff 时区边界 6/6、非默认时区账本冷重开 1/1 通过，均为 `--locked --offline`。冷重开测试确认原批准、事件与日报字节保持。没有模型调用、桌面消息、用户凭证或安装。

护栏只负责在规则变化时安全拒绝。未来升级 IANA 数据库须另立配置代际，保留 2025b 旧项目的投影能力，或经明确封存与接续迁移；不能直接改旧 bindings。旧项目就地换区仍未实现，也不是现有实施方案明确要求的正式验收先决条件。291 源码不在 288 的 0.1.18 安装包内，下一统一候选须独立冻结并复核。正式验收仍未完成。
