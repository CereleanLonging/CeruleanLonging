# 管理调用计数预检与实际预算出口

2026-10-15，批次 169。当前为开发源码增量，冻结的 0.1.10 内部候选不包含本批改动。

本批补充主、副指挥 OpenAI Responses 请求的计数适配与账本预留桥接。Host 和 API 执行器的金额预算拒绝保护继续生效；这里没有完成可用的金额预算产品入口，也没有真实供应商调用。

## 官方依据及适用范围

已搜索并打开 [计数指南](https://developers.openai.com/api/docs/guides/token-counting) 和 [计数 API 参考](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count)。指南说明计数覆盖请求结构，输出上限包含不可见 token；参考支持 model、instructions、input、text、tools、tool_choice、parallel_tool_calls。因此可为当前无工具、无共享会话的管理请求取得供应商计数，不能用字符数估算替代。

另核对 [官方定价页](https://developers.openai.com/api/docs/pricing)：模型计费存在缓存写入、上下文档位及服务档位等区别。本批不写入供应商价格，继续要求原用户批准的报价。所查页面没有提供足以判定计数请求自身收费方式的明确说明，不能据此承诺预检免费。

## 已实现的契约

- PreparedDecision 是原有完整生成请求。计数投影只去除 store、stream、max_output_tokens，其他七个字段逐值保持，包括完整 JSON schema；新字段、共享会话等超出当前合同的内容立即拒绝。
- count_decision 固定官方计数地址，复用现有 HTTPS、禁用代理/重定向/重试、响应长度和超时限制。计数失败不自动生成、不重试、不回退估算。
- CountedDecision 同时持有原请求和原客户端，不能 Clone/Deserialize。公开收据仅含请求身份、计数输入/响应摘要、计数与观测时间，不含上下文、密钥或私有推理。
- 计数凭据在本进程内最多存活 60 秒。这是本产品的保守有效期，不是供应商保证；预留及生成前分别检查。失效不自动重计、重发或退款。
- TokenCeiling 取实际计数和原有 4096 输出上限；缓存读、写均视为可能发生。原报价缺少任意一种缓存费率即拒绝，预留按所有输入类别中的最高费率计算。
- reserve_counted_management 直接从不可伪造的运行时计数对象构造 Reservation，再走原角色、项目、配置、方案、报价、累计余额校验。可序列化收据本身不能授予发送权限。
- 单元/跨 crate 夹具使用明确的 synthetic count；只有 dev-dependency 的 test-fixtures 特性导出夹具构造器。正常产品依赖不启用它。

## 解除金额预算发送拦截前必须完成

1. Host 异步预检：从当前认证用户及原批准推导 intent；预检前核对授权，完成后再次核对配置、方案、报价和账本 head，不能长时间占住宿主锁等待 HTTP。
2. 原始证据持久化：保存与请求绑定的计数收据，明确计数本身的授权/费用处理。报价必须覆盖实际服务档位、上下文档位和所有输入类别；未知不能当零。
3. 预留到 intent 的恢复：建立明确的持久准备/发出状态，解决“预留已落盘、原 intent 尚未落盘”时无法重开的窗口。缺少 intent 不能直接解释为未发送并退款。新格式如超出 reader4 能力必须重新评估读取代际。
4. 单次执行和结算：预留成功、原 intent 持久化后才允许生成；过期或启动失败保留原证据。结果使用原始管理日志回算，未知/持久化失败保留预留，不靠重发修复。所有管理用途共享项目累计余额。
5. API 执行器分别补供应商可靠上界、工具循环每轮的预留和最终结算；不能把本 OpenAI 无工具计数器套到其他协议、OMP 或桌面任务。
6. 完成上述接线的崩溃点/重启/并发受控验收后，再执行已获授权范围内的真实供应商验证。当前本地计数及账本测试不代替该验收。

下一工程优先项是第 3 项持久准备与恢复合同，其次接入 Host 异步计数。原型基础接入、168 完整回归及签名审计不因本批新增适配器而重复；只有集成新候选时才重做对应发布检查。
