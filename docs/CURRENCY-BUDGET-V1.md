# 金额预算：价格核算与持久预留

日期：2026-10-13，实施项128。当前为源码中的基础组件，尚未接入方案批准、运行调度和产品界面；不能认定产品已经支持金额硬预算。冻结0.1.9候选不包含本项。此前已通过的请求次数限制、API用量记录与接入证据保留。

## 数据与金额

`crates/domain/src/currency_budget.rs` 定义用户审阅的美元价格、请求预留和完整用量。金额使用JSON可精确表示的整数纳美元，价格使用每百万token的整数微美元；例如每百万token 2.50美元记录为2500000。不使用浮点、内置供应商价格、自动汇率或联网更新。费用是根据获批价格计算的金额，不能代替供应商账单、税费或订阅实际扣款证明。

价格绑定供应商端点、请求模型、允许返回的具体模型、有效区间和来源说明。相同模型名称在不同端点不是同一报价。报价过期后拒绝新的预留；已发送请求按原获批报价核算。主副指挥报价只允许OpenAI。

输入用量分为互不重叠的普通输入、缓存读取、缓存写入，输出另计。`ApiUsage::billable_usage` 沿用当前适配器的计数语义：Anthropic缓存用量独立，其他当前支持的API缓存读取包含在输入总数中。金额归一化要求完整缓存计数；缺字段时返回未知，现有token总量统计仍可使用。不会把缺失计数或缺失缓存价格填成零。

每个请求须给出包含全部输入的上限、输出上限、允许出现的缓存类别及证明摘要；所有可能的计费类别必须有获批价格。按允许类别中的最高输入价格预留，核算完成前不假设能获得缓存折扣。每个请求先汇总所有类别，再向上取整一次，避免低估，也避免分别取整的额外误差。

证明摘要只绑定证据，**不自行证明供应商会执行该上限**。接入运行路径前，必须由可信主机核验对应供应商、模型及当前请求的计量上界；不能用模型声称、未验证的上下文窗口参数或简单文本长度代替。无法证明上限的执行器不能显示为金额硬预算已支持。桌面/订阅Agent费用继续显示不可精确计量，使用独立的时间、次数限制。

## 预留账本

`crates/core/src/currency_budget.rs` 提供单写入者、只追加的账本。记录按序号和摘要串联，绑定项目、方案摘要和价格策略。记录先写pending并同步，再以不可覆盖方式发布；任何未完成发布、记录缺失、摘要不符或未知文件都会阻止重开。写入失败后原持有者禁止继续操作，保留现场。

运行路径应先持久预留，再记录原请求意图并发送。可用额度是限额减去已核算费用及全部未决预留；主指挥、副指挥和执行者共用这个计算。重复请求ID不能再次预留，即使原请求已经完成或证明未发出。

结果未知时保留全部预留，进程重启、取消、HTTP错误和本地超时都不能自动释放。可信主机证明尚未发送时，可记录NotSent并释放；Unknown不能再作为NotSent释放。收到原请求的完整用量后，可核算并释放预留差额。响应ID不能在同一供应商端点被重复计入另一请求。

实际模型不在报价中、用量超过上限、出现未获准的缓存类别或无法定价时，保存原观察为Unpriced，保留预留并阻止新增支出。这里的已核算金额为零不表示该请求免费；Unpriced及其完整预留必须在界面单独显示。请求与响应摘要不符则拒绝提交，不修改原账本。

## 接入顺序与剩余要求

1. 将价格与金额限额加入方案草稿、展示和批准摘要；账本的方案摘要在批准后绑定，不能把包含自身摘要的对象嵌入方案形成循环摘要。所有新持久字段必须受读取代际保护。
2. 将账本接入主副指挥与API执行者的唯一请求出口。主机验证批准、请求指纹、计费类别和上限证明后才可预留。未决请求与失败发送的处置必须引用原调用日志，不能根据调用者随意声明释放。
3. 支持跨方案修订的累计费用和未决预留继承。当前组件绑定单份批准，拒绝用新策略打开原账本；不能通过更换目录或创建新账本重置项目额度。接入前实现累计授权链和明确提高预算的批准流程。
4. 对取消、失联、晚到响应、缓存计数缺失、模型切换和进程重启做产品链差异验收，覆盖管理调用与并行执行者共同占额。
5. 界面区分已核算费用、未决预留、无法定价和实际账单未知，展示价格来源与期限；验证真实模型的计量上界后再开放金额硬预算。旧有产品拒绝金额预算的门禁在此之前保留。

本项测试证明整数核算、单写入者及本地账本状态转换。它不证明实际供应商价格、token上界、账单或产品端到端金额限制。下一批应推进批准和调度接线，不继续扩大基础账本测试替代产品落地。
