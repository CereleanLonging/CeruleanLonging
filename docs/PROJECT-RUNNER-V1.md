# 已批准项目的持续执行

2026-10-08。该组件把运行授权、副指挥分配、真实 Codex 编程、独立检查、主指挥收口串成宿主循环。完整 P2 仍需真实 OpenAI 指挥和用户业务验收；组件 Completed 不代表 P6 完成。

## 用户操作与状态

在“需求与计划”完成配置、生成方案并批准后，“项目持续执行”提供启动入口。启动确认说明模型、项目累计指挥请求上限和费用边界。核心绑定当前配置及方案摘要，先保存用户运行授权，再开始调度。保存配置和批准本身不会启动循环。

运行状态为 Active、Paused、Attention、Completed。用户暂停在下一次调度之前落盘，阻止后续派发；已发送任务仍收集结果，暂停不是远端取消。关闭窗口不撤销运行授权，常驻核心继续。重开读取已保存状态。

指挥要求补充信息、未知请求、任务中断或独立检查失败时进入 Attention，不自动重新发送或重跑检查。用户恢复明确确认此前注意事项，仍须满足原配置与批准。尚未完成的运行会阻止配置替换；未知操作、失败尝试的完整处置入口仍待实现。

## 调度顺序与恢复

1. 校验批准及配置摘要，等待项目现有工作线程完成。
2. 请求副指挥 Assign，先持久化请求意图，调用一次。Ready 回复通过真实会话与分配的两次确认桥接，才写 DispatchIntent 并发送。
3. Codex 提交后运行方案中批准的独立检查。已有失败检查不自动重跑。
4. 只有实际 Verify 后才请求 chief Accept，沿受信角色应用事务提交。仍有任务则继续分配，全部 Accepted 后保存 Completed。

run-control 使用顺序、哈希链和不可覆盖事件。用户才可写 Active/Paused；核心只能写 Attention/Completed，不能代替用户恢复。重开核对实际批准；Completed 还须在对应方案区间内找到每个任务的收口事件。残留写入或账本损坏拒绝打开。

请求、应用及发送继续使用已有持久化证据：未知请求不重发。Wait 已消费但 Attention 尚未保存即崩溃时，重开仍停下，不产生第二次付费请求。暂停与桥接确认相遇时再次核对授权；已确认发出的任务另行收集结果。
