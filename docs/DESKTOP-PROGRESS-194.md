# 桌面原任务运行中观察 / 194

适用：开发源码中的 Qoder 0.4.3.0 与 WorkBuddy 5.7.7.0。沿用原窗口、聊天、历史后缀及任务批准机制。本增量提供运行中的只读进度；不表示桌面自动建议已接通，也不替代旧接入验收。

## 当前实现

原 `desktop_background` 所有者继续唯一持有派发意图与项目账本。在原 TaskSend 运行期间，它每隔至少 5 秒启动一个只读 `taskprogress` 观察，最多 24 次，同时最多一个；观察走现有有超时、可取消、私有 Job 的桥接执行器。Rust 核对原审阅摘要、桥接摘要、应用版本、窗口进程及启动身份、文档/会话、模型显示标签、空草稿、至少两条历史后缀、轮次/提示控件身份和时间新鲜度。第一次成功观察固定可见轮次，后续变化只记观察错误。

桥接返回当前轮次的可见摘要、状态标签和身份，不返回回复正文、工具输出或推理文本。不聚焦、不输入、不 Invoke，不启动额外模型请求。WorkBuddy 的本地 UI 关联及模型显示标签依然不是供应商会话/后台模型认证。

任务停止、回读、完成或所有者故障时停止新观察，取消在途观察并等待它退出，丢弃晚到样本，随后才释放原任务所有权。进度仅在当前 Host 内存和快照中存在；两次重开不恢复观察、不重发任务。观察错误与任务错误分开。界面上的“已完成”仍仅是原聊天的状态标签；Submit、独立验证和 Accept 沿原链运行。

## 验证边界

- Rust：身份/新鲜度拒绝、错误隔离、状态标签不构成完成、限频与停止收回、原后台实际看见进度后才交付、两次重开不重发。
- Windows UIA：复用 `WorkBuddyStopWindow.cs` / `DesktopStopWindow.cs` 自有夹具，编译实际生产 C# 桥接。20 次进度读取/拒绝检查，另有 8 次基线准备；外部应用操作和消息发送为 0。
- React：实际 `DesktopTasks` 组件的 6 项检查，覆盖运行、界面完成标签、观察错误、无历史样本、待验收和旧快照。命令投递与网络请求为 0。
- 工具入口：`tests/desktop-progress-native.mjs`、`tests/desktop-progress-ui.mjs`，由 `scripts/test-desktop-progress-owned.ps1` 以私有 Job 持有；不能用真实应用替换自有夹具后直接运行。
