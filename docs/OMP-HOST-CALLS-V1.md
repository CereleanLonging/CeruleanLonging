# OMP 宿主工具调用与记录 V1

2026-10-10；承接 [工具注册](OMP-HOST-TOOLS-REGISTRATION-V1.md)。当前实现是可接入核心工具服务的协议层与独立持久记录，生产文件/命令处理器、RuntimeHost 调度接入和真实模型编程尚未完成。

## 调用路径

`WorkerTransport::execute_with_tools` 复用原单次 prompt 的唯一读取者、请求相关性、取消和终态判断。它要求此前注册成功，并在派发前重新核对会话身份、空闲状态及实际工具名称、说明、JSON Schema。原 `execute` 继续拒绝非空工具目录。

解析固定版本的 `host_tool_call` / `host_tool_cancel`，以宿主调用 ID 关联结果，以模型 toolCallId 防止重复动作。只允许注册名称；拒绝额外字段、非对象参数、控制字符 ID、控制 RPC 命名空间、重复或未知取消目标。每次尝试最多 128 次调用，同时最多 4 个处理器；参数帧与文本结果各限 64 KiB，取消帧还有独立数量限制。超限使本次尝试失败，禁止自动重发。

工具服务是受信核心接口 `HostService`。每次启动处理器前先调用 `record(完整 DispatchIntent, Dispatch)`；取消信号前记录 Cancel；结果写到 OMP 管道前记录 Result。参数和结果仅以 SHA-256 进入该记录，文本输出由工具服务负责内容限制。`start` 必须实施已批准权限、参数类型和目录/命令校验。JSON Schema 注册本身不会替代这项校验。

处理器以异步 future 运行，不新增 RPC 读取者。用户取消会先记录原 prompt 的 AbortIntent 和工具 Cancel，再发送 abort；OMP 的工具取消或异常 prompt 终态也会通知处理器。取消不等于撤销文件改动。任务终态必须等待所有处理器返回，再通过关联 get_state 确认远端空闲。处理器实现必须保证返回时操作已经结束，future 丢弃时清理自身资源；实际命令子进程的这一保障仍需后续服务实现和验收。

工具结果发布前的记录失败、处理器基础设施失败、超时、未知事件或重复调用都会中止通道；该连接不可再派发。结果在记录后、管道写入前崩溃时，记录证明本地产生过结果，不证明 OMP 收到结果。不会据此重放工具。

## 持久记录

核心 `OmpToolJournal` 使用独立全新目录，避免挤占 prompt journal 的五事件上限。记录绑定完整任务、尝试、修订、fence、工作目录、会话、连接、请求和模型摘要；每条带时间、序号和前一条哈希。只保存调用元数据与内容摘要。

每目录持有独占 OS 锁；每条上限 16 KiB、总共最多 384 条。发布顺序为新建 pending → 写入并 sync_all → 非覆盖硬链接到序号 JSON → 删除 pending。发布中断会使当前写者不可继续；重开遇到 pending、断序、额外文件、内容破坏或不同尝试均拒绝。

`create` 仅接受不存在的新目录；`open` 只供核查，不能继续写入。已请求取消但缺少结果仍属于 unresolved。此记录没有接管原操作、重放工具或判定独立验收通过的权限。实际工具路径隔离、目录句柄固定、受控命令 Job 生命周期和生产凭证使用将在服务层接入。

## 验证范围

- 协议测试：成功回传、OMP 取消、用户取消、重复调用、结果记录失败、记录先于副作用、四并发限制、未知目标/名称/字段拒绝，以及终态等待处理器清理。
- 文件记录测试：独占所有权、完整范围绑定、恢复只读、不重复执行、缺失/破坏/超大/额外记录拒绝、注入发布中断。
- 实际受控子进程终止：Dispatch 与 Result 的 synced、published、committed 共六个边界；父测试终止自己创建的子进程，重开原目录，并比较原始证据字节不变。临时测试目录随测试清理，日志及所列源码副本保留。

本批没有运行真实模型 prompt、真实工具读写或命令，没有重跑前端、原生 UI、发布安装，也未把 OMP 能力目录提升为已完成。原注册批次真实零 prompt 探测仍独立保留。最终测试统计与证据索引见当日交接。
