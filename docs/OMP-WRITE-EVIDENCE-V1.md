# OMP 写入前像与恢复核查 V1

2026-10-10。承接 [文件服务](OMP-FILE-TOOLS-V1.md)。已实现写入前保存原文、目标内容及绑定记录，并提供只读恢复核查。当前不会自动回滚、重新执行工具或把未知任务改成完成；经过用户复核的还原操作与产品界面仍待实现。

## 写入顺序和目录

每个新文件服务目录包含 `events/`（原 OmpToolJournal）与 `writes/<SHA256(callId)>/`。目录必须新建且位于项目之外；通用 OmpToolJournal 原存储格式不变。

在已有文件的独占句柄内先核验 expectedSha256，再写入以下只增不覆文件：before.bin（原文件存在时）、after.bin、prepared.json。每个文件均使用 create_new，并写入后 sync_all；原文最多1MiB、目标最多48KiB。prepared.json绑定完整DispatchIntent摘要、原工具Dispatch摘要、调用ID、相对路径、原文/目标长度及SHA。只有全部准备成功后才能修改项目文件。

新建文件先持久记录“原文件不存在”和目标内容，再使用 create_new 创建目标，避免准备备份失败时先留下空目标文件。父目录的创建仍可能先发生。

写入并调整长度、sync_all成功后生成 applied.json，绑定prepared记录摘要。随后沿用工具Result入账，再向OMP回传结果。applied记录仅证明本地写入步骤已走到该处；不证明工具结果已经回传，也不证明独立验收完成。

证据文件直接以不可覆盖名称创建，进程中断可能留下不完整证据；核查按严格字段、大小和哈希拒绝，不会使用残缺备份。目录和祖先句柄固定，数据文件通过非跟随reparse的句柄读取，并检查普通文件/单一硬链接限制。证据可含项目源文件原文，属于本地恢复数据；没有写入聊天记录或供应商请求。

## 恢复核查

`write_evidence::inspect(service_root, intent, call_id)` 先取得原工具journal独占锁；原服务仍持有锁时拒绝。然后核对原Dispatch、工具必须为cerulean_write_file、记录绑定、原文/目标哈希以及实际目录条目。

额外用path、目标原文和原文件SHA重新构造最初工具参数，并与原Dispatch的arguments_sha256比较。因此只改路径或目标内容，再重算prepared/applied哈希，也不能将备份绑定到其他写入。不同尝试、没有原Dispatch、额外/损坏/不完整记录均拒绝。

读取当前文件后报告以下状态：

| 状态 | 依据 |
| --- | --- |
| Original | 当前SHA与原文相同；或原先和当前均不存在 |
| Intended | 当前SHA与目标内容相同 |
| Other | 当前内容既不等于原文也不等于目标；可能是半次写入或之后的用户改动 |
| Missing | 原文件应存在而当前不存在 |

同时返回当前SHA、前后SHA、prepared摘要，以及applied记录和工具Result是否存在。该接口不修改文件。Other不能区分中断内容与后续人工修改，后续还原入口必须让用户复核，并把当前SHA纳入一次性决定，执行前再次核验。

## 实际验证

新增五组测试。覆盖前后内容保存、活跃服务锁排他、已完成写入/后续用户编辑核查、不同scope、损坏内容、重算哈希后的路径/目标替换、其他工具伪绑定、缺失Dispatch、重复证据发布、备份准备失败不修改原文件。

实际进程终止矩阵：新建和覆盖两种情况，各在prepared、partial、synced、recorded四个位置终止测试自行创建的进程，共八个位置。重开原证据并检查：prepared仍为原状态，partial为Other，synced/recorded为Intended；只有recorded存在applied，所有情况均没有工具Result。原文/目标备份保留，重复核查不改变项目内容。原文件服务RPC联合测试仍通过。

临时文件随测试清理，保留本批源码选择副本和检查日志。本批为本机实际进程中断测试，不能代表机器断电、磁盘固件缓存或介质故障保证。
