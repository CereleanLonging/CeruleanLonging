## 核心能力与包审查

`cerulean-runtime.exe --build-info` 在打开 Store、建立 IPC 或创建数据目录之前返回构建版本、平台、协议、升级锁定格式、备份格式与明确接受的备份写入版本。它不检查账户或调用模型。冻结脚本将该信息写入安装包清单，并核对三处 release runtime 摘要。

`scripts/test-windows-package.ps1` 需要包目录和已经审阅的清单 SHA-256。它固定清单和三项文件名称，检查版本/平台/格式能力、文件长度和摘要，再读取实际 Authenticode 状态。检查期间持有普通文件只读句柄，排除写入/替换；逐级目录句柄阻止改名，拒绝重解析点和文件硬链接。通过身份与完整性检查后，才运行候选核心的固定 `--build-info`，有时间与输出大小上限，实际能力必须与清单吻合。

默认发布路径要求清单已批准发布、调用者提供预期发布者证书指纹，且三项文件的实际签名有效并匹配该指纹。清单声称有签名不能替代实际检查。当前没有已签名发布包，正式签名成功路径尚未验证。

内部包必须显式传入 `-AllowUnsignedInternal`，且清单属于未发布的内部验证通道；只接受实际 `NotSigned` 或 `Valid` 状态。该选择表示操作者已经信任这份本地候选程序：摘要用于绑定审阅字节，不能证明发布者身份，查询也不是运行恶意程序的隔离沙箱。

示例只执行审查，不安装：

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File D:\test\CeruleanLonging\scripts\test-windows-package.ps1 `
  -PackageDirectory D:\test\CeruleanLonging\reports\p6-windows-package-011-20261012 `
  -ManifestSha256 604a287ca46d47ef6509fed3592a4182802eb6c669b59147383501c0d9b2ad1a `
  -AllowUnsignedInternal
```

结果绑定清单摘要和全部二进制摘要。脚本退出后释放句柄；后续安装事务必须重新固定并核对同一批字节，不能把早先审查结果当作永久信任。当前尚未实现该事务，也不会从这个命令自动安装、解除锁定或启动服务。

## 明确限定的备份兼容

此前备份读取要求写入版本等于当前程序版本；直接升到 0.1.1 会拒绝原 0.1.0 备份。现仅允许已核对的 schema 1 / writer 0.1.0、0.1.1，不根据语义版本号推测未来兼容。根路径、SID、清单摘要、文件集合与原有路径/句柄检查保持。

真实跨版本检查使用冻结的 096 开发核心 0.1.0 写出备份，由新 release 核心 0.1.1 核验并恢复到同用户原位置，五个文件逐字节一致；原目录另存到本次隔离测试目录。升级锁定保留，启动被拒绝；明确解除后原项目状态不变。新版写出的备份被旧读取器拒绝，未知写入版本与 schema 也被新版拒绝。

这里验证的是**备份容器读取兼容及原状态恢复**。没有改变账本格式，没有证明任意旧程序会拒绝新版活动数据目录；数据格式版本门槛、迁移事务与旧代码回滚仍需实现。旧 095 核心也不具备 096 的锁定保护。
