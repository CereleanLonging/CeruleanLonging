# 验收程序与批准绑定

2026-10-08。实现 P0/P1 的工具批准边界，并接入项目设置中的持久化工具登记；真实模型闭环尚未完成。

## 实际行为

每条 AcceptanceCheck 新增可选 tool，包含实际 exe 的绝对规范路径与 SHA-256、固定脚本/配置文件的路径与 SHA-256、允许的环境设置。全部字段参与完整方案批准摘要。program 保留为可读命令名称，实际进程只使用 tool 中的程序。

可信宿主在提交方案之前调用 PinnedCheck::describe，只读取普通文件并计算摘要；用户审阅页面显示程序、摘要、固定文件和环境。新宿主方案拒绝缺少 tool 的检查；历史契约允许缺省，以保留历史账本读取能力，缺省检查不能直接运行。

PinnedCheck::from_approved 根据批准的记录恢复绑定，不能自行省略文件或更新摘要。兼容构造方法 new 也必须与批准记录完全相同；相同字节但不同路径的 exe 不能替换已批准路径。创建绑定后一直保留批准摘要，运行前持有只读共享文件句柄并重新核验，防止检查后又将新文件摘要采纳为批准基线。变更工具需要新方案与新批准。

验证文件须在受测项目之外；项目本身通过受测副本与完整输入摘要关联。启动不使用隐式 shell、不查找 PATH，也不继承父进程凭证。当前允许环境设置：CI、NO_COLOR、PYTHONNOUSERSITE、PYTHONDONTWRITEBYTECODE、RUST_BACKTRACE、CARGO_NET_OFFLINE、NPM_CONFIG_OFFLINE，值均由枚举限制。SystemRoot/WINDIR 与每项检查的 TEMP/TMP 由核心提供；用户不能通过配置覆盖加载器、代理或凭证环境。

## 实证与限制

新增真实进程测试检查允许的环境确实到达子进程，PATH/OpenAI Key/Node 加载钩子未继承；修改程序路径/摘要、固定输入和环境均使批准失效，省略输入、输入变化后重新构建绑定、缺失工具绑定均拒绝。

检查入口为 scripts/check.ps1；本轮完整日志 reports/p1-tools-checks-20261008.log，51 项 Rust、4 项 Node 通过。严格 lint 为 reports/p1-tools-clippy-20261008.log。原生审阅与发布报告以最新交接列出的路径为准。

这只绑定显式列出的文件和少量设置，不构成整个语言运行时、动态 DLL、系统工具链、所有间接依赖或 OS 沙箱的身份保证。离线环境开关不等于禁止网络。版本升级审核、执行权限隔离、真实模型回调及项目最终集成仍需后续实现；当前不能据此声称 npm/cargo 等任意工程已受控验收。

## 持久化登记入口

项目设置中的“验收工具”允许填写名称、exe 完整路径、最多 16 个固定文件和上述环境设置。核心读取、规范化、计算摘要后写入 validators/<id>.json，包含固定 user 身份、时间、版本化结构和记录摘要。先同步临时文件再发布，复读验证结构与摘要。登记不执行程序、不批准方案、不创建验收任务。

每个核心最多 32 个登记版本，每份记录不超过 64 KiB，输入文件合计不超过 512 MiB，单文件仍受 256 MiB 限制。相同 ID、相同内容可重复返回；同 ID 的名称或文件内容变化拒绝，升级须另建登记。恢复读取历史摘要，不因原文件升级而重写。登记记录损坏会拒绝打开核心，以免悄悄遗失历史。可信宿主可通过 registered_validator(id) 获取描述放入待批准方案；此方法本身不创建方案或派发任务。

注册与恢复测试见 reports/p1-catalog-unit-20261008.log。最终完整回归 reports/p1-catalog-host-checks-20261008.log：Rust 53 项、Node 4 项通过。真实 UI/IPC 登记及重开恢复见 reports/desktop-smoke-2lSuP0/result.json；程序/摘要/环境审阅截图 workflow-tool-review.png 和登记截图 validator-catalog.png 已目视核对。

登记哈希目前同步运行，慢磁盘可能占用宿主请求处理时间，后续应纳入有界后台登记任务。登记只保存显式文件版本；记录摘要不提供同账户恶意重写的防护。原型/新工具登记与真实业务模型接入不可混为一谈。

## 接续顺序

1. 基础持久化登记和只读检查入口已完成；补工具生命周期、后台读取和依赖快照，工具升级绝不自动继承旧批准。
2. 给真实模型执行链提供受控回调，使用批准的绑定恢复验收器；模型不得自行写 verified 或替换程序。
3. 用真实编程项目验证用户批准、修改/diff、独立检查、异常恢复与主指挥收口；再扩齐供应商、桌面会话和发布范围。
