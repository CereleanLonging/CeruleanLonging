# 0.1.45 · 开发候选 / Development candidate

## 简体中文

本轮更新统一独立检查与加权验收，继续完善接入配置和桌面监督。

- 稳定提交的检查报告绑定方案、任务、尝试、命令、工具和源码摘要。完整项目使用最终集成的封存源码，归档落盘并回读后才进入盲评准备。
- 指令遵循、独立检查各占 50%；单票至少 80%、完整名册平均至少 90%，并保留全票通过。工具违规和过程证据不足计零分；未提供的逐项证据不计分。首版判据尚未校准。
- 评分结果收齐前继续密封，未通过的权重结果交副指挥分析；只有达标后才开放主指挥整体功能测试，再交用户确认。
- Qoder 监督在成功、操作改变或会话结束后停用过期建议；正常收尾只移除本任务的 Hook，保留其他设置。重启恢复原事件与状态，不自动重发。
- 模型选择支持搜索和明确确认，配置跨角色持久保存；完善 Key 按钮状态、CLI 会话进度和绑定桌面会话通道。
- 缓存列表隐藏零字节条目，改善预算、保存、下一步与生成方案的按钮布局。

工作台程序、核心与独立工具需要成套使用。新验收和监督数据使用 reader21 保护，旧程序不能忽略新门槛继续打开。升级前保留正常备份。

实现和边界见[独立检查与加权验收](../INDEPENDENT-CHECKS-WEIGHTS.md)，测试结果见[本版验证范围](../VALIDATION-0.1.45.md)。真实模型评分、桌面同会话设置恢复和跨接入完整流程仍需专用环境验证，不能以离线夹具结果代替。

## English

This candidate unifies independently checked evidence and weighted review while improving integration setup and desktop supervision.

- Stable-submission reports bind the plan, task, attempt, command, tool and source identities. Full-project review uses a sealed integrated delivery and a durably acknowledged archive.
- Instruction evidence and independent checks each contribute 50%. Every original seat must pass and reach 80%; the full-roster average must reach 90%. Tool violations and unverifiable traces receive zero weight. Missing criterion evidence earns no credit. Initial thresholds are uncalibrated.
- Scores stay sealed until every vote is received. Rejected weighted results go to the coordinator; only passing rounds unlock the lead's functional test and subsequent user confirmation.
- Qoder supervision expires stale advice after progress or context changes, preserves unrelated hooks during teardown and restores recorded state without resending requests.
- Searchable model selection, durable role settings, credential feedback, CLI progress, bound desktop review paths, cache filtering and action layouts are improved.

Use the GUI, core and independent executable together. Reader21 prevents older cores from ignoring new gates. Preserve a normal backup before upgrading. Real model scoring, desktop-session restoration and complete cross-transport workflows require separate environment-specific validation.
