# CeruleanLonging 0.1.40

公开预览 / Public preview · Windows x64 · lantu · MIT

## 简体中文

- 正常执行强制绑定各模型的独立目录；旧未隔离方案仍可查看和核对，但需重新规划、批准后才能派发。
- 主指挥规划和副指挥分配上下文明确模型身份、目录、负责文件及评审边界；不同执行端声明同一文件、大小写别名或父子重叠路径时拒绝方案。
- 评审仍只接收核心转交、独立验收工具处理的批准源码片段，不开放全库读取、文件工具、其他投票或总分。

同一模型后续任务可按原租约顺序修改自己的文件。按完整文件路径划分归属，不支持不同执行端拆分修改同一文件的行段；不宣称按内容相似度识别任意复制。API/OMP 使用核心文件工具限制，CLI/桌面沿用独立 Windows 账户和项目 ACL；缺少隔离条件即拒绝，不回退日常账户。系统文件、公开依赖和账户配置仍按 Windows 权限访问，并非全盘沙箱。

独立验收工具留在工作台程序目录。角色工作目录、客观测试、盲评全票与最终用户确认流程保持；评审不会提升执行端的目录权限。

## English

- Normal dispatch requires a bound directory for every worker model. Legacy unisolated plans remain readable and reconcilable, but require replanning and approval before dispatch.
- Lead planning and coordinator assignment contexts state model identities, directories, owned files and review boundaries. Plans are rejected when distinct workers declare the same file, case aliases or overlapping parent/child paths.
- Review still receives only approved source fragments prepared by the independent verifier and delivered through the core, without repository access, file tools, other votes or totals.

Successive tasks of the same model may modify its files serially under existing leases. Ownership is checked by whole declared file paths, not line ranges or arbitrary content similarity. API/OMP use host file tools; CLI/desktop retain isolated Windows accounts and project ACLs. Missing isolation blocks dispatch without falling back to the everyday account. System files, public dependencies and account configuration remain subject to Windows permissions; this is not a whole-disk sandbox.

The independent verifier remains in the workbench program directory. Objective tests, unanimous blind review and final user confirmation remain in place; review never expands worker directory permissions.
