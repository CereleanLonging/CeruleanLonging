# 0.1.44 · 源码缓存管理与接入体验更新

日期为2026-11-04，阶段为公开预览，发布者为lantu。

## 中文

- 编译与构建缓存统一进入源码工程临时目录，受管构建和测试结束后自动清理，保留空目录。
- “维护与升级”底部增加累计缓存监控，支持扫描体积、清理剩余缓存、查看活跃作业及累计清理量。
- 清理日志提炼后保存在 `docs/build-cache/cleanup-logs`，记录实际清理结果和待处理问题。
- 接入配置按工作台持久保存，连接方式默认折叠，主副指挥单选，执行端可添加独立配置。
- 改善Qoder会话关联、维护布局、退出提示和页面标题帮助说明。

缓存功能限定工作台源码工程。正在使用的缓存会保留，异常中断后的残留可重新扫描处理。源码缓存说明见 [缓存管理](../BUILD-CACHE-MANAGEMENT.md)。

## English

- Source compiler and build caches use dedicated temporary job directories with automatic cleanup after managed builds and tests, preserving empty directories.
- A cumulative cache panel at the bottom of Maintenance supports scans, cleanup, active-job visibility and reclaimed-byte totals.
- Distilled cleanup receipts are saved in `docs/build-cache/cleanup-logs`.
- Connection settings persist per workbench. Methods start collapsed, chief/deputy configuration is single-choice and workers support independent profiles.
- Qoder association, maintenance layout, exit guidance and heading help have been refined.

Cache management covers the workbench source checkout. Active caches remain protected, and interrupted leftovers can be scanned again. See [Source cache management](../BUILD-CACHE-MANAGEMENT.md).
