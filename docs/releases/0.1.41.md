# CeruleanLonging 0.1.41

发布者 / Publisher: **lantu** · Windows x64 · 公开预览 / Public Preview

## 中文

方案审阅新增默认关闭的“授权工作台为本方案创建隔离账户、设置项目目录权限”。勾选并确认后，核心先保存绑定当前方案、配置、目录及固定脚本的授权，再发起一次准备。授权只覆盖普通隔离账户和项目目录 ACL，执行模型不会成为管理员。

工作台已有管理员令牌时使用现有权限，否则由 Windows 请求一次 UAC，仍需用户本人确认。应用不自动点击安全桌面，不关闭 UAC，不提供模型可调用的任意管理员命令。取消、失败、重复批准、回执丢失和重开应用均不会自动重新提权。

在任务尚未启动时，可在项目设置核对原结果、明确点击“设置或补齐独立账户”发起新的一次准备，或单独打开模型登录。原设置未决时不能重新发起；任务开始后不允许修改该版账户权限。目录或配置变化须重新规划、审阅和批准。

首次使用这项授权启用 reader20 数据保护；此数据目录之后须使用 0.1.41 或更新的兼容核心，升级前请保留备份。未勾选的批准保持原格式，既有批准不会被追加授权。模型登录、任务启动、独立验收和最终用户确认仍分别进行。

同时调整两项离线测试中 PowerShell 的冷启动等待时间，避免忙碌的 Windows CI 在测试子进程尚未就绪时误报；产品关闭超时和错误判断保持。

## English

Plan review adds a default-off option to authorize ordinary isolated account creation and project directory ACL preparation. After confirmation, the core durably binds the authorization to the plan, configuration, directories and fixed provisioning script before starting one preparation. Workers do not gain administrator membership or tokens.

An already elevated workbench uses its existing token. Otherwise Windows requests one UAC consent, which the user must confirm. The application does not click the secure desktop, disable UAC or expose arbitrary administrator commands to models. Cancellation, failure, duplicate approval, lost acknowledgements and reopening never automatically repeat elevation.

Before tasks start, project settings can reconcile the original result, explicitly start a new preparation, or open a separate model login. An unresolved preparation blocks another attempt; once a run starts its account permissions remain locked. Changed configuration or directories require replanning and fresh approval.

First use enables reader20 protection, requiring version 0.1.41 or a newer compatible core for that data directory. Keep a backup before upgrading. Unchecked approvals retain their prior format, and existing approvals cannot acquire extra authority. Model login, task start, independent verification and final user confirmation remain separate steps.

Two offline tests also allow more time for cold PowerShell startup on busy Windows CI hosts. Production shutdown limits and exit-result checks are unchanged.
