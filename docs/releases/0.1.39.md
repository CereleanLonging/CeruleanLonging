# CeruleanLonging 0.1.39 · 公开预览 / Public Preview

Windows x64 · Publisher: **lantu** · MIT

## 简体中文

- 新增随工作台分发的独立验收程序，固定绑定并核对摘要，实际承担脱敏分片、核票和全票判定；项目客观测试与最终用户确认保持。项目专用检查配置收进高级设置。
- 编程项目初始目录为 `D:\test\coding`，可自行修改；验收工具留在工作台程序目录，不迁移已关联项目。
- 修复主指挥桌面接入在无项目时入口变灰的问题：关联项目目录后可继续配置，并保留“当前 Codex 聊天”的选择。等待配置读取完毕再定位到相应角色，不因慢读取而丢失导航。
- 已有桌面绑定保留会话标识和副指挥设置；更换接入方式只修改待保存草稿。保存配置、请求方案、审阅批准和启动任务仍分别操作。离开页面会取消未完成的配置跳转。
- 缩小侧栏退出按钮，并增加与版本号的间距；确认退出及后台正常停止机制保持。
- 文档提炼项目选择框统一布局，未配置时提供明确说明及配置入口。自动提炼仍要求已保存的 API 主指挥，外部 Codex 聊天不会被偷偷替换为 API。
- 桌面使用指向完整程序目录的快捷方式，GUI EXE、核心及资源需保留在一起。

保留 reader19 和现有数据格式；本版拆出独立验收进程并改善前端流程，不增加真实供应商推理质量结论。桌面主指挥仍通过已有外部会话领取、回填协议工作，不自动创建聊天或发送消息。

## English

- A separately executed verifier ships with the workbench, with a fixed, hash-checked binding. It prepares redacted fragments, validates ballots and checks unanimity; objective project tests and final user confirmation remain. Project-specific checking tools are advanced settings.
- Project registration starts at `D:\test\coding` and remains editable. The verifier stays in the program directory; existing projects are not relocated.
- Desktop-chief setup no longer becomes inaccessible when no project exists. Register a directory, then continue with Current Codex Chat selected. Role focus waits for configuration loading, including delayed reads.
- Existing desktop bindings preserve the session identifier and deputy settings. Changing the connection method edits only the draft; saving, requesting a plan, approval and execution remain separate. Leaving the page cancels unfinished configuration navigation.
- The sidebar exit control is smaller and separated from the version label. Confirmation and normal backend shutdown are unchanged.
- Document refinement has a consistent project selector, explicit empty-state guidance and a setup entry. Automatic refinement still requires a saved API chief; external Codex chats never trigger an implicit API fallback.
- Use a desktop shortcut to the complete program directory, keeping the GUI, runtime and bundled resources together.

Reader19 and the data format remain unchanged. This update introduces the independent verifier process and improves frontend flow, without a new live-provider quality claim. The desktop chief continues using the existing external-session claim/reply protocol; it does not automatically create chats or send messages.
