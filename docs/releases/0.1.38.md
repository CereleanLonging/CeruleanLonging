# CeruleanLonging 0.1.38 · 公开预览 / Public Preview

Windows x64 · Publisher: **lantu** · MIT

## 简体中文

- 本地 `.md` 导入改为：选择文档 → 已配置的主指挥自动提炼 → 审阅、修改 → 确认读入草稿。提炼归纳目标、任务、验收标准、约束、疑问和背景，并保留原文与引用供对照。创建计划时可选择使用哪个已保存项目的主指挥。
- 移除文件大小、正文长度、行数和手工记录条数的固定导入上限；长文档分段提炼，完整保存确认后的草稿。实际处理仍受本机资源、供应商上下文及项目调用额度约束。执行方案的任务数量和安全权限仍遵循原项目配置。
- 选择文档后即可能调用所配置的 API 主指挥并计费。每个非空分段只发送一次，计入主副指挥请求额度；失败停止后续分段，不自动重发、不应用半成品。停止后续提炼不保证撤销已发出的请求或费用。
- 结果未确认前不改写现有草稿；保存、请求规划、批准和启动仍分别操作。切换项目、修改配置／草稿或进入不可操作状态，会使旧结果失效。
- 提炼请求只提供文档分段，不提供文件、命令或联网工具，不执行 Markdown／HTML、不加载文档中的链接。引用必须能在原分段中定位；这不能证明摘要完整或正确，仍需用户审阅。
- 仅支持 UTF-8 `.md`。需先保存可用的 API 主指挥配置；绑定外部 Codex 聊天的主指挥尚不支持后台自动提炼，不自动改用其他模型。金额预算尚不可执行的项目仍保持原门禁。
- 提炼调用和结果保留在本地指挥记录中；重开工作台不重发旧请求。更新前请备份；使用新提炼记录或大文档后不要直接用旧核心打开同一数据目录。

沿用 reader19 容器格式；新增记录用途不代表旧版本可以读取新记录。[支持范围](../../SUPPORT.md) 中的既有验收范围保留。本轮验证使用合成模型回包及真实本机 IPC，不增加真实供应商提炼质量结论。

## English

- Local `.md` import now follows: select a document → automatic refinement by the configured chief → review/edit → confirm into the draft. Results group objectives, tasks, acceptance criteria, constraints, questions and context, with the original text and verbatim citations available for review. Create Plan can use the chief from a selected saved project.
- Fixed import limits on file size, text length, line count and manual record count have been removed. Long documents are processed in segments and confirmed drafts are stored in full. Available memory, provider context limits and project request budgets still apply. Execution-plan task limits and permissions remain governed by the project configuration.
- Selecting a document may immediately call the configured API chief and incur charges. Each nonempty segment is sent once and counts against the management request budget. Failure stops later segments without automatic retries or partial application. Stopping later segments does not guarantee cancellation or refund of requests already sent.
- Existing drafts remain unchanged until confirmation. Saving, requesting a plan, approving and starting work are separate actions. Changing the project, configuration, draft or availability invalidates older results.
- Refinement supplies document segments without file, command or browsing tools. Markdown/HTML is not executed and embedded links are not fetched. Citations must occur in the original segment; that does not prove a summary is correct or complete, so user review remains necessary.
- UTF-8 `.md` only. Save a supported API chief configuration first. A chief bound to an external Codex chat cannot refine automatically in the background; no fallback model is selected. Existing gates for unsupported monetary budgets remain in place.
- Calls and results remain in local management records. Reopening does not resend earlier requests. Back up before updating; after storing refinement records or large documents, do not open the same data directory directly with an older core.

The reader19 container remains in use; the new record purpose does not imply backward readability. Existing [support scope](../../SUPPORT.md) remains unchanged. Validation uses synthetic model responses and real local IPC, without a new live-provider refinement-quality claim.
