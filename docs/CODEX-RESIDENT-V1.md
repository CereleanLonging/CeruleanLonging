# Codex 常驻执行与原生对账

2026-10-08。本批把已验证的派发库接入 RuntimeHost。用户界面断开不会取消后台 worker；P2 整体仍待真实主副指挥及完整业务流程验收。

## 批准与执行生命周期

TaskExecution.worker 可携带提供方、模型和本地程序绝对路径/SHA-256，进入完整方案批准摘要；界面审阅显示全部字段。旧记录缺省此字段，原摘要不变，但新常驻派发要求补齐后重新批准。RuntimeHost::describe_codex_worker 只读生成描述，不启动模型；可处理最多 512 MiB 的执行器。独立验收工具仍使用原来的 256 MiB 单文件限制。

start_codex 是受信副指挥回调，不存在允许用户注入角色或任意命令的派发 IPC。调用核验方案版本、批准、任务依赖、请求/权限/金额策略、worker 路线和未使用的 Attempt ID。先保存启动记录，随后专用线程持有项目账本和 Codex 子进程；会话创建后落 Assign，再由正式派发库先写 DispatchIntent、发送一次并收集回执。

执行前锁住已批准的程序，读取并核对摘要；锁保持到客户端关闭，拒绝期间写入/替换。实际程序必须在项目目录之外。实际返回模型、提供方、目录和会话仍由适配器确认。这不构成主副指挥身份认证或全部动态依赖的系统隔离证明。

同一项目执行与验收互斥；全宿主两类后台任务合计最多 4 个。项目移交给后台线程后，主服务用缓存快照回答查询，完成时取回账本；运行中禁止同目录或上下级目录再次登记。正常退出会等待正在执行/不确定的任务，关闭窗口不退出核心。

## 状态与恢复

codex-jobs/<project>/<attempt>.json 保存启动描述和状态，最多每项目 1000 项，每文件 64 KiB。启动记录不是事实来源：重开时核对原方案/批准/worker 字段，并依据 Submit 或 Reconcile Submitted 账本恢复提交状态。没有账本证据的“已提交”被改为 Unknown，不会自动重派；被替换的模型/程序描述拒绝加载。

界面展示连接中、执行中、核对中、已提交、未知和启动失败。Unknown 的“核对原会话”经窄 ReconcileCodex 命令启动后台只读对账；只允许原 Unknown Attempt，不能借此创建会话或发送提示。状态轮询显示最终结果。对账恢复到 Submitted，仍需独立验收与主指挥收口。

线程 panic 会重新打开账本触发恢复；通道无结果或恢复失败时保留不确定状态，不释放项目供重派。尚未形成 Assign 的正常启动错误标为 Failed；其 Attempt ID 仍不可重复使用。Assign 后但发送意图前的故障可能需要进一步人工对账，目前保守阻止重派，不伪称已实现所有恢复分支。

## 本批真实证据

`reports/p2-resident-codex-20261008-023403/result.json`：既有 Codex 0.160.1 / ChatGPT 登录 / gpt-6.1-sol，1 次编程 turn/start 生成 sum.mjs；独立固定 Node/脚本的 10 项检查通过。常驻服务经真实同用户命名管道观察了 270 次断开/重连，最长查询 2 ms；这是本机小夹具测量，不能外推为大项目性能保证。

原会话 `01a117a5-3888-7131-a147-36f036c921bb`，原轮次 `01a117a5-3a3e-7663-af89-f8bf66cb06ef`。原账本保留，复制其前缀至 DispatchIntent 模拟确认丢失；新 RuntimeHost 根据账本得到 Unknown，再经用户对账命令读回同一真实轮次，新增模型发送 0 次，重开仍为 Submitted。测试总用时约 88 秒。

测试方案、批准及副指挥入口由集成夹具预置，不能计作真实主副指挥/实际用户验收；没有 Accept 事件。原生 UI 的独立结果以本批最新交接列出的 native-codex-recovery 报告为准，不能只凭组件渲染宣称按钮有效。
