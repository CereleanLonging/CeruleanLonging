# Codex 执行观察 v1

2026-10-09。本批接入有容量限制的工具完成元数据、宿主保存和只读桌面详情。它是副指挥监督的输入基础；异常事件生成、已批准监督策略、建议调用与在途送达尚未实现，不能据此放行 P2/P5 或完整 P0–P6。

## 实际行为

- 复用 Codex 唯一协议读取者，仅处理 `item/completed` 的 `commandExecution`、`fileChange`。本机 Codex 0.160.1 的导出 schema 保存在 `reports/codex-supervision-schema-20261008`；协议来源为 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。
- `turn/start` 前准备观察；ACK 到达且原 `Started` 已可靠入账后，才激活对应 thread/turn。提前通知先有限缓存，错误轮次不会混入当前尝试。
- 每次执行最多保存 128 条，按接收顺序编号；相同 item/元数据去重，冲突或错轮次单独计数。短锁冲突和溢出记为遗漏，不阻塞协议取消路径。
- 只保存种类、状态、退出码、宿主接收时间和摘要。命令与 item ID 仅保存 SHA-256；不保存命令明文、输出、diff、工作目录、凭证或私有推理。SHA-256 用于关联与完整性校验，不代表加密保密或远端签名。
- 宿主将投影写入 `worker-observations/<project>/<attempt>.json`，临时文件完成同步后替换；单文件读取上限 256 KiB。绑定 project/task/attempt/revision，历史读取还核对原 Started 的 thread/turn。损坏或关联不符时拒绝。
- `ReadWorkerObservation` 不推进调度或补写工作流，只返回按需详情；普通 Snapshot 不携带上次详情。正在执行时读取共享内存，结束后可从保存记录读取。只读执行对账不覆盖原记录。
- 需求与计划页面新增“执行观察”。可查看两类事件、遗漏/拒绝/去重数及关联摘要；有缺口时明确提示证据不完整，不能自动纠偏。

`finished` 仅表示采集函数正常结束，不代表任务成功、观察完整或已独立验收。进程中断或保存失败可能只留下旧的未结束记录，也可能没有记录；前台给出相应状态。只有工具完成事件被覆盖，没有通知不能直接判定卡循环。自动监督接入时必须另核对活动状态、当前策略、预算和观察完整性。
