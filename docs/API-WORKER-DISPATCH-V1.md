## 批准与权限

TaskExecution 新增可选 apiWorker，包含固定供应商/地域目标、模型、文件权限、最大轮次、最大工具次数、单轮输出上限、累计用量停止阈值和请求时限。所有字段进入原 PlanRevision 批准摘要，改动后旧批准失效。API worker 不需要虚构本地可执行程序，不占用 OMP 身份；本地 worker 与 API worker 不能同时配置。旧任务省略该字段的JSON序列化保持不变。

模型只获得 apiWorker.fileTools 中批准的读/写工具，且不得超过项目权限。项目 RunCommands 仍供独立验收器使用，不把命令工具交给 API 模型。自动运行中监督及金额硬上限尚未实现，此版本拒绝API方案声明这两种能力，避免批准内容和执行能力不一致。

API 使用自己的供应商 adapter ID、api-worker-v1 版本及控制端请求身份；它描述本地逻辑执行会话，不冒称供应商支持可重连的会话。每轮原始响应 ID 另存于单次日志。主副指挥限定OpenAI的规则不变。

## 实际执行顺序

1. 核对用户批准、策略版本、任务、attempt、绑定及刚分配状态；已有派发历史或原目录时拒绝重新发送。
2. 分配新的 API attempt 证据目录，保存批准身份，建立文件工具记录，提交工作流 DispatchIntent。
3. 每轮建立独立 CallJournal；先保存意图，再调用固定供应商地址，完整响应落盘后才处理工具提议。
4. 工具提议须匹配获批工具，关联调用ID和参数摘要。文件调用意图持久化后才读写；结果持久化后才进入下一轮API请求。
5. 收到最终文本且工具全部结束后，封存每轮记录头、工具记录头、用量、执行回执和真实产物摘要。
6. 验证全部原始证据及文件未变后提交为 Submitted。独立验收器通过之前，主指挥不能 Accept。

文件服务复用原有路径保护、Windows目录固定、UTF-8分块读取、预期SHA写入、写前像及应用记录。工具日志现在按明确的作用域类型共用实现；API记录使用API作用域，OMP记录仍使用原DispatchIntent及原JSON摘要。API错误结果会回传模型；部分文件I/O或记录结果不明时停止，不把未知写入当作成功。

## 限额、取消和恢复

项目请求额度约束每一轮API请求，而不只按启动attempt计数。已有完整封存的API尝试按原轮次计数；没有完整封存的尝试保守占用其批准的全部轮次预约，不能因结果不明获得新的调用额度。它可能比实际调用数量多，不是账单。历史证据损坏会阻止继续分配额度。

单次任务还受独立轮次、文件调用次数、整体时间、请求时间和输出上限约束。最后可用轮次返回新的工具提议时，在执行该工具前停止。累计token是收到usage后的停止阈值，不是请求前的输入token硬预算；一次请求可能越过阈值。达到阈值后不运行新工具或发起下一轮。金额统计及价格策略未实现，不将缺失价格计为零。

用量按协议统计：Claude合计非缓存输入、缓存读取、缓存写入和输出；OpenAI及兼容协议的缓存读取属于输入总数的分项，不重复相加。所有累计运算检查溢出。[Claude用量说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[OpenAI Docs缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)。

本地取消、整体超时、供应商错误、额度耗尽和部分证据不确定均保留 Unknown；取消不回滚已完成文件写入，也不证明供应商免计费。整体超时会丢弃本地在途请求；当前同步文件操作有单文件边界，未证明硬实时中断。

恢复只读原始completion封存、逐轮日志、工具记录及产物，不重新联系模型、不重放工具、不重新采集产物来伪造原完成证据。封存后、提交前注入中断时，完整原证据可以恢复到Submitted；产物变化、轮次损坏、工具记录缺失、发布残留都拒绝。尚无API恢复产品入口，也未验证实际进程终止/断电矩阵。
