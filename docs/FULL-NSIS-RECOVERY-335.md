# 335：已确认升级后的显式保数据恢复

本项是独立 Windows 验收工具，接续 334 固定 310/0.1.21→315/0.1.22 的正常完成操作，执行“卸载当前315程序、核对数据保留、完整重装310”。它不接管失败或 Unknown 的前向升级，也不是产品自动回滚。代码在 `reports/full-nsis-recovery-335/driver/`；最终检查与独审以该目录上级的完成索引为准，索引生成前不视为整项通过。

## 输入与执行顺序

只接受具体原 `334/run-*/result.json`，连同用户固定摘要、原机器指纹记录及摘要。334顶层工程检查报告不能充当真实安装来源；真实CLI拒绝受控测试记录，内部测试参数不在CLI开放。原记录的成功标签、退出码、超时/错误、自动动作、原意图命令、安装器摘要、目标目录、环境、原八格登记与完整包身份必须一致。历史JSON只作为证据引用，不恢复旧Popen权限。

1. 在原独立测试机/账户重新核当前315的完整八文件库存、登记、数据/hold/冷备份。按本机Known Folder独立派生原资源协调路径，核它们与原334记录及原持久意图一致。
2. 取得同一组稳定资源锁，并跨卸载与重装全程保持。按原334意图摘要保存不可覆盖的恢复消费记录；换run或重新生成计划不能绕过。原334资源意图和消费记录始终保留。
3. 只复制当前315安装目录中的卸载器到本次隔离runner，核有界普通单链接文件与逐字节摘要。原卸载器句柄在启动前关闭，避免阻挡NSIS删除；runner副本保持固定。
4. 原始命令为 `"<隔离runner>" /S _?=<原安装目录>`，末尾目录不加CRT引号、不传/P或/UPDATE。父writer在启动前交给NSIS，原hold和资源锁保留。观察原child及两路输出，不强杀、不凭PID重开、不自动重发。
5. 原child明确exit0、EOF、无超时和观察错误后，重取父writer并核卸载中间态：安装目录可空或不存在，任何文件或空子目录残留都拒绝；全部卸载键必须absent，原产品位置键及其他登记状态逐格保持；数据/hold/备份全部保持，两次观察无漂移。HKCU32、64或双视图须与原已验证归属一致，不把某个视图永远为空当作前提。
6. 只有中间态通过，才记录新的源安装阶段意图并启动一次原310完整setup，命令沿334原始 `/S /NS /D=<原目录>`。仍由同一组资源锁覆盖，不因安装目录已不存在而重新派生或释放互斥。
7. 核源两程序、SQLite通知、卸载器共四文件及完整登记；315额外资源不得残留。新源卸载器不能仍是315观察到的身份，但可以与初始310相同。再核数据/hold/备份、所有原始引用和两个阶段的终态文件；各保护句柄正常退出后才给内部恢复完成状态。

baseline、恢复意图、恢复消费记录、各阶段意图及后验记录都在首次发布时固定摘要，之后只核原摘要，不通过“重新算一个新摘要”接受中途修改。两个阶段各自绑定原进程、原命令及四份终态文件；这些文件在下一阶段前及最终收口都再次按原长度/摘要核对。

八格登记沿用既有工具的四个身份字段采集，包含两种hive、两种视图和产品/卸载两种键；这不是注册表所有值的完整备份。卸载器来源与原意图、实际进程和当前文件相关联，不宣称独立密码学来源认证或排斥任意外部安装程序。

## 使用边界

入口为 `run_full_nsis_recovery.py --forward-result <原334/run结果> --forward-result-sha256 <摘要> --origin <原机器记录> --origin-sha256 <摘要> --run <335下新run-*目录> --allow-unsigned-internal`。仅在对应独立环境使用，不在当前工作主机执行。`--observation-seconds` 是首次观察间隔，不是强杀期限；超时会继续等原child，但不能走正常完成出口。

本工具始终保留hold，不启动产品、不解密凭证、不改信任、不手工删除注册表，也不自动清理任何未知残留。失败或Unknown只保留现场，下一阶段不启动；如果进程仍需观察，原资源锁由拥有者继续持有。

当前固定包为未签名内部候选，因此有明确内部选项；该选项不等于正式发布认可。恢复后的产品首启、解除hold、真实独立Windows运行，以及签名/许可/费用/其余接入门槛仍独立保留。受控普通文件检查不能代替真实NSIS升级与恢复。

334/333的冻结源码与旧失败材料不修改。335针对登记视图和执行链补差异检查，不重跑旧接入、已成功或Unknown模型任务，也不为这套脚本重打产品包。
