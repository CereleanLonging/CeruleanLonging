# 308 SQLite 查询读取边界

承接 302–307。事件账本仍为唯一权威；本轮约束可丢弃 SQLite 缓存的读取成本，不改变批准、Unknown、Accept 或派发权限。

## 实现范围

- 读取连接打开前，核对已打开文件句柄的长度，超过 128 MiB 即回退。该限制没有放进通用发布检查，因此超大的旧缓存仍可由私有临时库原子替换。
- 每个只读连接设置 SQLite 原生限制：字符串/BLOB/整行 32 MiB + 64 KiB，SQL 64 KiB，列 32，表达式深度 64，复合 SELECT 8，编译指令 65536，函数参数和绑定参数 16，附加数据库/触发器递归/辅助工作线程 0。没有修改 SQLite 进程全局内存设置。
- 连接设为 query_only、trusted_schema=OFF、1 MiB 建议页缓存、mmap=0、忙锁等待 0。每 1000 条 VM 指令检查一次；累计约 800 万条指令或经过 2 秒后中断。它是协作式限制，不是硬性墙钟超时，也不覆盖单个底层调用的全部耗时。
- 发布与读取共用原 schema 1 的固定 SQL：6 个表、5 个显式索引和 4 个 UNIQUE 自动索引。最多回读 16 个 schema 对象，逐项核对类型、名称、所属表及 SQL；未知视图、触发器、额外/缺失索引均回退。旧 schema 1 字节形式保持，不升级账本读者代际。
- 元数据直接借用 SQLite Text 字节，head 至多 32 KiB、digest 至多 64 字节，最多读取 2 行；不先复制成 String。
- payload 直接由 `get_ref` 取得借用字节，通过长度限制后才用 `serde_json::from_slice` 解析。一次完整读取的五张结果表共用 16 MiB 累计预算；计划页、摘要页、日报和未完任务各自的一次查询也用同一上限。
- 完整读取与日报按权威期望行数加一设置 SQL LIMIT；多余行在 JSON 反序列化前拒绝，缺行同样拒绝。分页继续按主键范围、最多 256 行和原逐行摘要核对。未完任务按主键扫描，避免按可编辑索引结果排序产生临时排序表。
- 保留全量 fingerprint、分页/任务/日报逐行证明和 SQL 列与 payload 一致性检查。任何失败均走既有权威内存回退；查询自身不修复缓存，不提交事件，也不重发任务。

## 验证与证据

修改前副本和摘要位于 `reports/index-read-bounds-308/before/` 与 `before-manifest.json`。启用现有 rusqlite 0.40.2 的 limits/hooks 功能，不引入新包或联网更新；Cargo.lock 应保持原摘要。

新增 7 项差异用例覆盖完整/分页/日报/未完任务的大 cell、跨表累计超量、额外行在反序列化前拒绝、递归视图与未知 schema、元数据长度与类型、SQLite 原生长值及递归工作中断、超大缓存的回退及重建后事件逐字节不变。复用 302–307 的异步、队列/容量、Unknown、恢复和只读回退检查。实际结果以本轮报告为准，不在执行结束前写成通过。

## 边界与后续

16 MiB 是一次读取的 JSON 输入总量，不是解析对象实际堆大小，也不是所有并发查询的总内存上限。原生长度限制、页缓存建议值和文件上限同样不是全进程 RSS 上限。权威完整历史、主线程索引行构造/日报预渲染以及解码对象放大仍需独立评估。

新核心真实历史回查遵守 307 的计划：原根严格只读、前后全部文件摘要核对，284 的 Unknown 以管理历史为证据；不能移动 guard、更改原路径/SID 或用普通可写 Host 打开冻结原根。完整 Host/隔离副本兼容另记范围。

本轮不运行模型，不读取 Key，不改签名或信任，不打包安装。297 冻结候选和正式验收缺口保留，正式验收仍未完成。
