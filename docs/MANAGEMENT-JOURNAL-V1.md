## 执行路径

`start_management_decision` 是受信 Rust 编排入口，不是允许 UI 任意指定上下文或冒充角色的 IPC 命令。核心从已登记项目的执行快照、验收工具目录、接入目录和需求文字构造上下文，并计算完整摘要。主副指挥用途由 Purpose 区分，客户端继续固定官方端点、禁止工具、不自动重试。

本地凭证读取与运行时初始化完成后，先在 `management-decisions/<operation>.0.json` 发布意图，再启动后台线程。文件经同目录临时文件写入、sync_all 和 rename 发布；按当前 Windows 文件系统语义实现，不宣称任意断电下绝对持久。记录包含请求 ID、项目、用途、模型、上下文摘要及原始上下文，供恢复核对。需求与任务文字是产品数据，不应在其中填写密钥；凭证不属于此记录。

线程只调用一次客户端。正常服务每 100 ms 的既有轮询会处理结果，UI 关闭不停止线程。返回成功后，核心再验证请求模型、响应 ID、实际模型格式、用途和状态摘要，然后以 `<operation>.1.json` 保存响应或 Unknown；包含版本、时间、前一条摘要和本条摘要。不保存供应商原始错误、认证头或推理正文。

线程断开、客户端失败或返回值不合规均保留 Unknown；这里的 Unknown 指“没有可应用的已验证决定”，也包括供应商明确失败，不能推断是否计费。保存失败保留原意图，禁止用重发请求修补磁盘记录。相同操作 ID 重复提交被拒绝；同项目已有未处置决定时，即使更换 ID 也不能发送。

## 恢复与权限

重启只读证据并校验顺序、摘要、上下文及响应，未见完整响应的意图恢复为 Unknown，绝不重新启动线程。残留 `.pending`、损坏记录、无意图响应、超大文件均拒绝打开，需要后续明确恢复处置；不能静默忽略。当前目录最多 1000 个操作，每条记录最多 256 KiB，请求上下文还受客户端 64 KiB 限制。

运行中标记仅来自内存中的接收句柄；磁盘上的意图本身不证明仍在运行。活动请求期间禁止替换/删除 Key，正常服务停止被拒绝；当前内部入口最多 4 个指挥请求。主副指挥请求限额尚未与项目预算统一，不应提前向 UI 开放自动调用循环。

`management_decision` 读取结果时重新构造当前上下文，状态或目录变化则拒绝旧决定。Ready 仅表示已有有效响应证据；不会生成用户批准、执行代码、写入 Propose/Assign/Accept，也不会自动消耗或移除决定。当前同项目仍会被此决定占位，这是后续应用/显式处置事务尚未实现的限制，不是完整调度能力。

存储在 RuntimeHost 既有单写锁下使用；摘要可以检测意外损坏，不抵御同 Windows 用户恶意重写整套本地证据。运行时权限与操作系统隔离继续按 P1/P2 门槛验收。
