# 服务档位与上下文报价合同 / 177 / 2026-10-16

176 完成独立的 Rust 计价领域合同和管理请求审阅适配器。177 将报价配置、用户批准与原金额账本接通，并增加 reader8 保护和维护入口；本批检查结果以独立报告为准。这些开发改动尚不能用于真实预算执行，原生产金额门禁保持。旧报价及原计数凭据不会自动变成新请求许可，没有生成新的发行候选。

## 解决的问题

旧 PriceQuote 只有一组固定费率；请求不指定 service_tier，响应也不保存实际档位。这样的报价不足以证明整个请求的费用范围。新 ScopedPriceQuote 同时绑定官方端点、请求模型、请求档位、实际模型集合、实际档位集合、完整输入 token 区间、有效期与用户审阅来源。当前只支持官方 OpenAI 和按请求计费（PerRequest），不会把其他供应商或按整段会话计费的模型套入这一合同。

每个实际模型与档位组合必须覆盖本次输入的整个闭区间，不允许空档、重叠或自动选择近似价格。选档使用普通输入、缓存读取、缓存写入的总和；价格作用于整次请求的各项 token。预留计算遍历每个可达区间，在该区间内取最大责任，再取所有模型与档位组合的最大值。因此低区间更贵、缓存写入贵于普通输入也不会低估。金额使用原整数纳美元算法，整次请求求和后向上取整。

请求省略档位、显式 auto 和显式 default 是不同身份。结算仅匹配响应中的实际档位，缺失、超出报价范围或缓存用量不完整均不能得出金额；不按请求档位补值。fast 与 priority 保留原字符串，只有报价明确覆盖才能使用，不能全局互换。报价覆盖是用户审阅的条款，不能因此宣称供应商保证了这些结果范围或费用上限。

## 管理请求审阅适配器

ScopedDecisionDraft 为 Plan、Assign、Accept、Advise 构造明确 service_tier=default 的无工具请求，保留新生成体摘要。其计数投影剔除 service_tier、store、stream、max_output_tokens，保留原七个上下文字段，包括完整结构化输出 schema；新增字段必须重新审阅。新生成请求与旧请求摘要不同，计数投影相同不意味着旧 CountedDecision 可以替新请求授权。

该对象没有发送方法，不能转换为旧 PreparedDecision 或 CountedDecision；也不能从反序列化审计记录恢复发送能力。review 接收的输入区间只用于条件计算，不是可信 token 上界。ScopedPricingReview 私有持有原报价和区间，后续价格评估不能悄悄换成新费率。响应只保留摘要、管理决策是否可解析、金额或无法计价的原因，不输出上下文与私有推理。决策不可用和费用计算独立：格式错误的模型回答也可能产生费用。
