## 路线与权限

主副指挥先使用官方 Key 路线，Codex 继续作为执行者。原型 Codex 指挥测试只证明“未观察到工具调用”，不能证明全部工具注册和上游身份已隔离，因此不将原型直接放行。

正式客户端固定 `https://api.openai.com/v1`，仅 HTTPS、系统 TLS 校验、不接受自定义端点或代理环境配置、不跟随重定向、不自动重试；连接时限 15 秒，总请求时限 90 秒，回复上限 2 MiB。回环测试入口私有，生产入口不能传入其他 URL。

Responses 请求不注册工具，明确 `tool_choice=none`，使用严格 JSON Schema。OpenAI 官方文档支持这些请求字段：[Responses 创建接口](https://developers.openai.com/api/reference/python/resources/responses/methods/create)。同时设置 `store=false`、不流式、4096 输出 token 上限；这些是客户端策略，不应宣称供应商所有保留行为都已被禁用。

主指挥可返回计划或验收建议，副指挥可返回分配或纠偏建议；各用途都可选择 wait。返回值包含当前状态摘要，过期摘要、错误角色、额外授权字段、工具调用、不完整回复、拒绝/多条歧义输出都拒绝。计划验证非空任务、唯一 ID、合法依赖及无环 DAG。实际 worker/validator 是否属于配置目录、验收是否绑定当前产物，仍由核心集成层校验，不能仅因 JSON 合法就执行。

只保留响应 ID、请求/实际模型、token 用量和结构化决定，丢弃推理项目。API 模型别名可能返回具体版本，因此两个模型字段分别记录，不把字面相等作为身份判断。官方端点与系统证书信任不是抵御被攻陷操作系统的保证。

## 本机 Key 入口

运行 `target/release/CeruleanLonging.exe`，在“接入管理 → OpenAI 主副指挥”输入 Key，选择“加密保存 Key”，再“检查官方 API 连接”。Key 不用发到聊天。检查仅 GET /models，不生成模型任务；列表可见不证明支持结构化指挥，也不证明还有生成预算。

核心把 Key 用 Windows DPAPI 当前用户模式加密，附加工作台数据根目录绑定信息，写入 `credentials/openai.dpapi`。因此换用户或迁移根目录后需重新配置，不能把文件直接搬走当作可用凭证。写入通过临时密文文件同步后替换；不写明文或把 Key 放进事件账本、快照和诊断错误。

SecretInput 的 Debug 输出脱敏，受控 Rust 秘密字符串和 DPAPI 明文缓冲区在释放时清理。输入框是密码框，提交后清空，重开不回填；提供显式删除按钮。不能据此宣称浏览器、序列化和 HTTP 栈所有临时内存副本都已安全擦除。DPAPI 保护静态文件，同一 Windows 用户的恶意程序仍在现有安全边界之外。

连接检查由独立线程运行，结果轮询；检查中禁止替换/删除 Key，正常核心退出等待检查结束。更换 Key 清除旧认证和模型列表，核心重启仅显示已配置待检查。不导入、枚举或读取其他应用的密钥。
