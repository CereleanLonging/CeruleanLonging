# OMP 文件复核与还原界面 V1

2026-10-10。承接 [文件还原核心](OMP-FILE-RESTORE-V1.md)，现在已接入桌面「需求与计划」中的「OMP 文件恢复」入口。本次完成隔离任务的真实 Tauri → 本地 IPC → 核心 → 文件 → 重启核查流程；没有调用供应商或真实模型。

## 用户流程

界面列出当前 Unknown 的 OMP 尝试，按每页16条读取写入记录。选择文件后并列展示当前内容和还原后内容、字节数、文件摘要及还原记录状态。UTF-8预览最多16KiB，在字符边界截断；二进制只显示类型和大小。不存在的原文件明确标识，确认操作将删除本次新增文件。

「复核并还原」打开确认窗口，需要勾选内容确认才能提交。取消窗口没有文件副作用；提交期间禁用重复操作。文件或工作流证据变化会使旧复核失效，必须重新读取。成功后显示结果并关闭重复还原入口，原任务继续保持Unknown，需要后续核对。

## 核心接口与范围

新增ReadOmpFiles和RestoreOmpFile类型命令，客户端只提交项目/任务/尝试/调用标识、分页和复核摘要，不提交文件路径、证据目录或角色。服务端从已登记工作流派生固定证据位置，由现有本地用户IPC通道进入，核心固定使用项目的user主体。普通stdio Store拒绝这些宿主专用命令，模型工具目录没有还原操作。

复核和还原都不推进调度。宿主拒绝活动项目运行、指挥未决事务、执行/验收未收口、其他活动或未知任务、待修订/需重开账本。仅接受当前Unknown原尝试。底层再次核查原批准、派发和工具证据、完整复核摘要，并在实际文件句柄下检查版本。

读取结果是本次响应专属ompFiles，普通快照不带预览，不使用共享选择游标。还原后读取独立repair记录，展示已还原、还原后变化、还原中断或记录不可用；存在repair目录时不再给出新的执行摘要。

这里沿用当前本地用户通道的信任边界，不构成抵御同一Windows用户下任意恶意程序的隔离保证。阻止同项目其他活动是当前保守准入规则，跨进程资源租约和OS沙箱仍待实现。
