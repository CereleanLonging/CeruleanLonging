# 核心数据冷备份与原位置恢复

094 实现 `--workbench backup create|verify|restore`，复用原核心单写锁和凭证存储。命令在本机离线执行，不启动核心，不请求模型，不操作桌面应用。原型接入结论沿用 [继承入口](PROTOTYPE-REUSE-BASELINE.md)，旧证据不重跑。

## 操作方法

先通过既有退出流程停止该数据目录的核心。若有未决任务导致停止被拒绝，先沿原任务处置流程处理；备份命令不会强行停止核心。

```powershell
# 备份父目录应已存在；最后一级备份目录必须不存在。
cerulean-runtime.exe --workbench --data-dir "D:\WorkbenchData" backup create --to "D:\WorkbenchBackups\20261012-01"
cerulean-runtime.exe --workbench --data-dir "D:\WorkbenchData" backup verify --from "D:\WorkbenchBackups\20261012-01"
```

两者输出 JSON，包含 `manifestDigest`、原始数据路径、文件与目录数量、总字节数及范围说明。备份完成后仍可正常使用原数据目录。校验不启动或重放账本。

恢复前保留现有目录，并确保原路径不存在。工具不会替用户删除、改名、覆盖或合并现有目录。审阅备份来源与摘要后，再提供确切摘要：

```powershell
cerulean-runtime.exe --workbench --data-dir "D:\WorkbenchData" backup restore --from "D:\WorkbenchBackups\20261012-01" --manifest-digest "校验输出的完整SHA256摘要"
```

必须使用原 Windows 用户及原规范化路径；恢复后核心保持停止。凭证采用原 DPAPI 密文，熵包含数据路径，不解密导出 Key。迁移到其他路径、用户或机器不在这个命令的支持范围内。

## 保存范围与失败行为

- 保存核心数据目录的普通文件、空目录及原始字节，包括事件、批准、未知状态日志、配置和凭证密文。零字节 `writer.lock` 文件也保留；备份期间获取原根锁及遇到的嵌套写锁。
- 外部项目、Git worktree、外部验收器、模型 CLI 安装和第三方桌面历史不包含在内。它们的引用仍是原路径；需要另行保留。
- 拒绝活动写入者、硬链接、目录内重解析点、异常文件类型、大小写冲突和不支持的 Windows 文件名。备份必须位于源目录外。
- 文件读取句柄禁止并发写入和替换；目录句柄禁止替换。清单逐项记录路径、类型、长度、SHA256，校验拒绝多余、缺失、损坏、重复、越界路径及不支持的清单版本。
- 当前上限为 16,384 个条目（含目录和根锁）、16 GiB 文件总量、16 MiB 清单。超限报错，不截断。大量同时持有的句柄可能先触及系统资源限制，同样报错。
- 先写同父目录 `.cerulean-pending-*`，同步文件并核对全部内容，再使用不带替换标志的 Windows `MoveFileExW` 发布。目标在操作途中出现也拒绝覆盖。失败不清理暂存目录，保留现场；只有命令成功发布的目标才作为正式备份或恢复结果。
- 退出码沿 CLI：输入错误 2、维护拒绝 3、输出失败 5。输出失败可能发生在操作已经完成之后，先检查目录和清单，不自动重试。

摘要用于核对已审阅内容，不是发布者签名。备份含完整业务数据，只有原凭证文件保持 DPAPI 加密；没有额外把整个备份加密。该工具依赖本地文件系统和核心单写约定，不用于网盘、多主机写入或对抗同一用户的恶意进程。

## 验收边界

专项验证覆盖原批准记录重开、原位置 DPAPI 解密、未知状态原始字节和空目录保留，以及损坏/缺失/多余文件、篡改清单、活动锁、错误用户/位置/摘要、硬链接、并发替换和现有目标拒绝。另以实际 CLI、常驻核心、中文空格目录验证备份—校验—原位置恢复—重开；不调用模型或用户桌面。最终检查和失败日志见 [094 验收索引](../reports/p6-cold-backup-20261012.json)。

首次专项发现 `std::fs::rename` 会替换已有空目录，违反恢复约束，已改为 `MoveFileExW` 的禁止替换调用并验证。旧失败日志保留。

这是字节级备份，不证明任意输入账本的业务语义健康，也不改变原核心重开的校验规则。恢复较早备份可能缺少备份后发生的外部派发记录；不能据旧快照自动重跑任务，需先核对原远端尝试及保留的数据。这一版不提供活跃项目的自动历史回滚。

清单 schema 1 和当前产品版本只约束备份读取格式，不构成所有历史构建的数据库兼容承诺。尚未证明：跨路径/机器迁移、数据格式转换、升级失败自动恢复、旧版本降级兼容、真实断电/磁盘满完整矩阵、干净安装卸载及签名发布。完整 P6 仍未验收。
