# 303 SQLite 后台更新与有界查询

2026-10-23。继承 [302 的索引一致性底座](SQLITE-DERIVED-INDEX-302.md)，只补异步、生命周期与查询差异。最终状态与完整日志以 [303 报告](../reports/sqlite-async-303/summary.md) 为准；此项不是正式验收或新包签收。

## 本轮行为

- 每个账本最多有一个执行中的索引构建、一个可被最新快照替换的待处理快照。空闲线程退出，下次需要时再启动，不以队列积累每个历史版本。当前仍需在主线程制作已核验的内存快照，未声称消除所有 O(n) 处理。
- 事件发布、领域状态更新与原有日报投影完成后，提交索引快照并返回。SQLite I/O 和摘要生成在后台进行；等待中的索引不影响授权、派发、资源租约或返回最新读取视图。
- 每次读取仍绑定当前权威链头。后台还未追上时，立即回退已核验内存；普通滞后不显示为坏账本。后台构建失败保留诊断，不撤销事件或重发模型任务。
- Store 和 DurableWorkflow 在释放自己的 writer.lock 前显式 join 索引线程，处理完已经排队的最终快照。退出不强杀线程。冷备份不能在写锁仍被持有时开始；账本 Drop 返回后没有遗留索引写入。
- `wait_for_index` 是显式维护/诊断等待接口，主线调度不调用它。它等到当前链头且后台静止；超时只报告原工作仍被持有，不能据此重启构建或模型请求。303 首轮发现相同链头旧回执可能过早满足等待，已补确定性回归并修复。
- 计划和历史分页使用 SQLite 主键范围与最大 256 条内部限制，工作区仍保留原 20 条/64 KiB 页边界。每个返回行与后台从权威快照生成的逐行摘要比较；删行、改序号、伪造批准等会回退。每页无需反序列化全部缓存。日报只读自己的表，跨日查询核对完整的预期任务集合，防止索引条件篡改造成漏项。
- `inspect_existing` 仍不启动索引线程或写缓存；冷恢复、事件唯一权威、Unknown 禁止重发、未知 sidecar 保留等 302 规则继续有效。没有数据库 schema/reader generation 变更，也没有新增依赖。

## 验证范围与测量限制

新增受控门闩证明后台暂停时主线可继续提交和读取，pending 只保留最后版本；另验证 Drop 保留写锁直至后台排空、随后冷备份稳定。复用 302 的删除/损坏/超前/落后/路径链接/只读/冷恢复/冻结旧读者检查，异步情况下先使用明确等待接口取得需要的检查点。

千事件测试既包含控制后台暂停的合并用例，也包含没有门闩的自然追加。当前样本中，自然 1000 条追加约 4.65 秒，连同尾部构建约 5.20 秒，实际启动 36 次构建；20 条末页内部查询中位约 1.59 毫秒，完整缓存核查约 68.32 毫秒。数据为本机调试构建、合成计划、5 次查询样本，比较对象是完整 SQLite 缓存核查，不是原先纯内存查询或完整 GUI 延迟。不得将这些数字当作 72 个真实模型效率样本或整机吞吐认证。

旧分页回归中的目录快照改为先等待后台静止；超大内存夹具显式更新测试缓存后再框定只读请求。原大小拒绝、内容绑定、事件字节和只读目录不变断言保留，未通过关闭保护让测试变绿。
